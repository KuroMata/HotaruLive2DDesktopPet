# 方案：给桌宠一个"自己的脑子"

> 目标：让她**不依赖 WorkBuddy** 也能思考；能启动程序；能做简单日常聊天。
> 约束：不要复杂。

---

## 一、先说结论

**把"启动程序"和"聊天"当成两件完全不同的事。**

- **启动程序不需要 AI。** 用一张本地命令表 + 关键词匹配就够了，响应 30 毫秒，不会认错，也不会莫名其妙打开不该开的东西。
- **聊天才需要一个语言模型。** 其余部分（气泡、口型、语音、表情）你的项目里**全都已经有现成的**。

这个区分是整个方案里最关键的一点。让模型去"决定启动什么程序"是新手最容易踩的坑：它慢、会幻觉、而且不安全。

---

## 二、为什么现在不算"她自己的脑子"

现在的对话走 `app/js/workbuddy-bridge.js`，通过 ACP 协议接 **WorkBuddy 本体**。这条路有三处限制，正好对应你说的"单独"：

1. **WorkBuddy 没运行时，她没有脑子**——输入框打了字只会报"链路未就绪"。
2. **她附着在 WorkBuddy 的当前会话上**。代码注释里记了：每次提问上游会把整段会话历史回放一遍（实测 29 万字符、1400+ 事件），所以要专门写逻辑把回放段丢掉。这意味着她跟你共用的是**WorkBuddy 的记忆**，不是她自己的。
3. **人格不稳定**——她说话像谁，取决于上游那个会话里发生了什么。

要"单独拥有"，就得有**自己独立的会话历史、独立的人格设定、独立的记忆**。

## 三、三层结构

```
用户说话
   │
   ▼
[第 1 层] 意图层 —— 本地规则，零依赖，零延迟
   │  匹配命令表？→ 是 → 执行（启动程序 / 打开网页 / 控制自己）
   │
   ▼ 没匹配上
[第 2 层] 闲聊层 —— 语言模型（本地或云端）
   │  可用？→ 是 → 生成回复（带情绪标签）
   │
   ▼ 不可用
[第 3 层] 兜底层 —— 现有台词池 + 模板
```

**好处是逐级降级**：没装模型也照样能用（第 1 层 + 第 3 层），装了才升级到完整体验。不会"因为模型挂了她就哑了"。

### 第 1 层：意图层（必做，且最有用）

一个 JSON 命令表，放在 `app/data/commands.json`：

```json
{
  "apps": [
    { "name": "计算器", "alias": ["计算器", "算个数", "calc"], "type": "exe", "target": "calc.exe" },
    { "name": "网易云音乐", "alias": ["放首歌", "音乐", "网易云"], "type": "exe", "target": "E:\\CloudMusic\\cloudmusic.exe" },
    { "name": "项目文件夹", "alias": ["打开项目", "桌宠目录"], "type": "dir", "target": "D:\\live2d-companion" }
  ],
  "self": [
    { "name": "隐藏", "alias": ["你先躲一下", "隐身"], "action": "hide" },
    { "name": "锁定", "alias": ["别乱动", "固定住"], "action": "lock" }
  ]
}
```

匹配方式用最朴素的：别名包含匹配 + 拼音兜底（`pinyin-pro` 已经在依赖里了，所以"fangshouge"也能匹配"放首歌"）。不需要分词，不需要语义模型。

**你机器上现成可用的**：网易云音乐（`E:\CloudMusic\cloudmusic.exe`，已注册 `orpheus://` 协议，可以唤起并播放）。

### 第 2 层：闲聊层（模型）

见下一节选本地还是云端。回复要求模型**额外输出一个情绪标签**，例如：

```
[happy] 好呀，我帮你打开~
```

标签直接喂给已有的表情系统（`exp3/` 下那 12 个表情：脸红、晕眩眼、唾液、害羞 1/2……）。这一步是"能思考"变成"看得出她在想"的关键。

### 第 3 层：兜底

退回现在的 `idle-lines.json` / `click-lines.json` 台词池，按关键词选一句。她永远有话可说。

## 四、脑子放哪：本地 vs 云端

你的机器是 **RTX 3080（10GB 显存）+ 64GB 内存 + 5800X3D**，跑本地模型毫无压力。

| | 本地（Ollama） | 云端（DeepSeek 等） |
|---|---|---|
| 聊天质量 | 7B 够日常闲聊，复杂问题会笨 | 明显更聪明 |
| 首次成本 | 装 Ollama（约 500MB）+ 下模型（约 4.7GB） | 只要一个 API key |
| 后续费用 | 0 | 很便宜，但要用钱 |
| 断网 | 照样能用 | 直接哑掉 |
| 隐私 | 聊天内容不出本机 | 内容上传到对方服务器 |
| 速度 | 40+ 字/秒，首字约 0.3 秒 | 首字约 1 秒 |

**我推荐本地。** 三个理由：

1. 桌宠聊天是很私人的东西，本地跑更符合"她住在你电脑里"这件事。
2. 断网、限流、涨价、接口改版，全都影响不到她。
3. 你的显卡正好闲着——跑 7B 模型只占 4.7GB 显存，不影响别的。

**具体选型**：`qwen2.5:7b-instruct-q4_K_M`。中文闲聊是同尺寸里最好的一档，4.7GB，3080 上约 40–50 字/秒。想要更快就换 `qwen2.5:3b-instruct`（2GB，质量明显下降，但"简单日常聊天"也够）。

**一个必须注意的技术点**：渲染进程直接请求 `127.0.0.1:11434` 会被浏览器当跨域拦掉（Ollama 默认不允许跨源）。解决办法是**走主进程代理**——`main.js` 里已经这么代理 ACP 了（`/api/v1/acp`），再加一条 `/api/llm` 转发即可，架构完全一致，也不需要让用户去配 `OLLAMA_ORIGINS` 环境变量。

## 六、安全红线（必须遵守）

1. **模型永远不能直接执行程序。** 它只能输出文字和情绪标签。真正启动程序由第 1 层的白名单决定——不在表里的东西一律不执行。
2. **白名单由你手动维护**，不放"任意命令执行"这类口子。
3. 启动前做路径校验，防路径穿越与参数注入。
4. 高风险操作（关机、删除、关闭程序）默认**要二次确认**，让她反问一句"真的要关吗？"

---

## 七、记忆（做到"够用"就停）

不要做向量数据库，太重了。用一个 JSON 文件：

- **短期**：最近 20 轮对话，滚动保留。
- **长期**：一条几百字的人物摘要（你的称呼、你常做的事、她的口头禅），随对话缓慢更新。

这就足够产生"她记得我"的感觉了。
