## 一、需求拆解

| 编号 | 需求 |
|---|---|
| R1 | 设置里可自由选择 Live2D 模型（选模型路径或关键文件即可载入）；**替换后的模型默认不沿用原来做好的语音** |
| R2 | 台词可在设置中自由更改；语音可用 TTS 预设音色读**中/日/英**三语；也可由使用者关联**自己录好的音频**播放对应台词 |
| R3 | 关联模型的 `exp3`（表情）与 `motion`（动画）文件，让使用者能播放模型自带的表情与动画；设置页新增分页，可自行选择读取这些文件，并设置**快捷键或触发方式**（例如点击模型时播放对应表情/动画） |

## 二、现状盘点（读代码得到的事实，部分与旧文档不符）

1. **模型资源服务**
   - `/models/*` → `MODEL_SERVE_BASE`（`main.js` 第 189 行，**启动时求值的常量** = `CONFIG.modelServeBase || app/models`）。
   - `sendModelFile()`：**明文优先**；同名 `.enc` 存在才用 AES-256-CBC 解密返回。
   - 结论：**外部模型目录里的明文文件可以直接被服务**，不需要先加密。

2. **当前模型 Hotaru2024 的真实情况**（解密 `model3.json.enc` 后确认）
   - `FileReferences.Expressions` **已经列了 12 个表情**（bodysuit / change / changehand / Coat / dizzy / Handgun / rabbit / saliva / Shoes / shy1 / shy2 / SnipingRifle），文件在 `exp3/*.exp3.json`。
     → 也就是说**表情其实已被 pixi 加载**，缺的只是"触发入口"。
   - `FileReferences` **没有 `Motions` 段**，但目录里确实存在 `idle.motion3.json`（40s 循环）与 `sleep.motion3.json`（4s 循环）。
     → 动作**完全没接**，需要补 `Motions` 引用才能播。
   - `Groups` 里有 `EyeBlink`，`LipSync` 为空。

3. **模型加载链**
   - `app.js: initLive2D()` → `l2d.load(box, CONFIG.modelUrl)`，只读 `modelUrl`；模型库根目录由主进程常量决定。
   - 渲染层完全不感知"模型库"，只认 `/models/...` 这个 URL 前缀。

4. **台词 / 语音链**
   - 数据：`app/data/click-lines.json`、`idle-lines.json`（结构 `{idx, text, jp, emo[]}`）。
   - 预生成音频：`app/data/lines/*.wav`（click/idle × cn/jp 各 10 条）+ `manifest.json`（给出 cn/jp 文件名与文本）。
   - 播放：选中台词 → `l2d.onPickLine(pool, idx, entry)` → `app.js` 按 `manifest` 播对应 wav；缺文件则回退 `ttsSpeak()` 运行时合成。
   - 语言：`idleDisplayLang` / `idleVoiceLang`，目前**只有 cn / jp**，没有 en。

5. **TTS 引擎**：`cosyvoice` / `indextts` / `edge` / `sapi` / `tone`。
   - `app.log` 实测：**`edge(unavailable)`** —— 微软在线音色当前不可用（中日英预设音色最全的恰恰是它）。

6. **设置页机制**：`app/settings.js` 是 schema 驱动（`SCHEMA` 数组 + `makeCtrl()` 工厂），已有 `toggle/select/range/number/text/screenSelect/extraParams/musicStatus/audioSource` 等控件类型。**新增分页与自定义控件成本低**，不用重构。

7. **主进程缺口**：目前**没有**文件/目录选择对话框（`dialog`），也没有素材枚举接口——R1/R2/R3 都要新增。

## 三、技术方案

### R1 · 模型自由切换

**数据**
- `config.modelLibrary`：模型库根目录（如 `D:/SteamLibrary/.../Live2DModels`）。
- `config.modelUrl`：沿用现有字段，改为由选择器写入。
- `config.lineProfile`：`{ "<模型标识>": "<台词档 id>" }`，用于 R2"新模型不沿用旧语音"。

**交互（设置页新增「模型」分页）**
1. 「模型库目录」：文本框 + `浏览…`（`dialog.showOpenDialog({properties:['openDirectory']})`）。
2. 「模型列表」：扫描 `<库>/**/*.model3.json`，读每个的 `Name`（缺失则用文件夹名）列成下拉/卡片，附 `模型名 · 目录 · 文件大小`。选择即写 `modelUrl = /models/<相对路径>`。
3. 也支持「直接选 model3.json 文件」：自动把库根推导为该文件的上一级目录并写回。
4. 「载入」按钮：**热重载**（销毁旧 PIXI Application 后重新 `load()`，不退出进程）。
5. 改动 `modelLibrary` 需重启（因为 `MODEL_SERVE_BASE` 是启动常量）——**除非采纳下面的改造**。

**一处建议改造（推荐）**
把 `/models` 路由里的 `MODEL_SERVE_BASE` 从"启动常量"改成"每次请求读 `CONFIG.modelServeBase`"。
改动约 1 行，收益是**换模型库目录也不用重启**，体验显著更好。风险：几乎为零（`safeJoin` 的目录穿越防护保持不变）。

### R2 · 台词可编辑 + 语音来源

**引入「台词档（profile）」概念（这是"新模型不沿用旧语音"的落点）**
- 存放：`app/data/lines/profiles/<profileId>.json`
- 内容：两条池（click / idle），每条台词形如
  ```json
  {
    "text": "博士，怎么啦？", "jp": "ドクター、どうしました？", "en": "Doctor, what is it?",
    "emo": ["neutral"],
    "voice": { "cn": {"src":"file","file":"click_cn_00.wav"},
               "jp": {"src":"tts","engine":"cosyvoice","voice":"","lang":"jp"},
               "en": {"src":"file","file":"D:/MyRec/en_00.wav"} }
  }
  ```
  `src` 三态：`file`（项目内 wav）/ `tts`（运行时合成）/ `abs`（用户自录音频绝对路径，或复制入库）。
- 模型 → 档 的映射写在 `config.lineProfile`；**默认 `Hotaru2024` 指向现有的 hotaru 档**（等价当前行为）；**其他模型未绑定时落到 `default` 档**——默认档不含 Hotaru 的 wav，仅按需 TTS 合成，即"新模型默认不用原语音"。

**设置页新增「台词」分页**
- 池切换（点击 / 待机）；表格列：`中文 | 日文 | 英文 | 情绪 | 语音来源 | 试听 | 删除`，底部「+ 添加台词」。
- 语音来源每行可选：
  1. `TTS 合成` —— 选引擎 + 语言 + 音色，点「生成」调现有 `/api/tts` 生成并落盘到 `data/lines/<profile>/`，行内绑定文件名；
  2. `本地音频` —— 「选择文件…」按钮选定 wav/mp3；
  3. `沿用预生成` —— 兼容旧数据。
- 语言扩到 **中/日/英**：`idleDisplayLang` / `idleVoiceLang` 增加 `en`；`manifest` 结构增 `enText` / `en` 字段。

**TTS 预设音色清单**
- 新增主进程接口 `pet:listVoices(engine)`，返回该引擎的预设音色（含语言标签）供下拉。
- **前置问题**：`edge` 当前不可用。中日英音色覆盖最好的是 edge；cosyvoice 支持中/英/日预置 speaker，index-tts 以中文为主。
- 因此方案里把「修好 edge」列为**可选项**：修好 → 三语预设音色最省事；不修 → 用 cosyvoice 的多语言 + 自录音频兜底。

### R3 · exp3 / motion 关联与触发

**素材发现**
- 渲染层在 `load()` 完成后，从 `model.internalModel.motionManager.definitions`（`{组名: MotionSpec[]}`）与 `motionManager.expressionManager?.definitions`（`ExpressionSpec[]`）取出清单，上报主进程（沿用 `reportModelParams` 的模式，新增 `pet:reportModelAssets` / `pet:getModelAssets`）。
- 表情这项**现在就有数据**（model3.json 已列 12 个）；动作这项当前为空，需要下面第 3 步补齐。

**播放接口（`live2d-loader.js` 新增）**
- `playExpression(nameOrIndex)` → 内部调 `model.expression(...)`
- `playMotion(group, index, force)` → 内部调 `model.motion(group, index, MotionPriority.FORCE)`

**让 motion 可播（关键前置）**
- Hotaru2024 的 `model3.json` 没有 `Motions` 段，pixi 不会加载任何动作文件。两种做法：
  - **做法 1（推荐，服务层）**：`main.js` 的 `/models/*` 路由在返回 `*.model3.json` 时，按 `config.modelAssets` 的映射**动态补写 `Motions` 段**（例如把 `idle.motion3.json` 归到 `idle` 组、`sleep.motion3.json` 归到 `sleep` 组）。明文与 `.enc` 两条路径都要处理。
  - 做法 2（渲染层）：手工构造动作定义喂给 `motionManager`。可行但要绕 `ModelSettings`，受库版本影响，不推荐。
- 设置页提供「添加动作」：选模型目录下的 `*.motion3.json` + 填组名，写入 `config.modelAssets`。表情若某模型没写进 model3.json，同样用这套注入。

**「表情与动作」分页（设置页新增）**
- 左列：当前模型可用素材（表情名 / 动作组·索引·文件）。
- 右列：每个素材的触发方式，可多选：
  - `点击模型时播放`（并可选"点击随机播一个"）
  - `快捷键`（窗口内 / 全局 `globalShortcut`）
  - `待机随机播放`
  - `手动按钮`（底栏或托盘菜单加一项，便于测试）
- 存储：`config.assets.bindings = [{kind:'expression'|'motion', id|group+index, triggers:[...]}]`

**已知风险（需要你知情）**
- 模型自带表情是**直接写参数**（exp3 里是 `Add` 混合），与现在"情绪层 `_express()`"每帧写五官参数**会打架**。需要约定：播放模型表情期间，情绪层挂起对这些参数的写入（或先停情绪层），播完恢复。这是 R3 里最需要仔细处理的一处。
- `idle.motion3.json` 是 40s 循环待机动作，若开启会和现有"参数合成的待机动作（呼吸+摆头）"重复叠加，需要二选一或加权重。
